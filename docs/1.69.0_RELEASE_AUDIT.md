# Lifely 1.69.0 — Release audit and competitive assessment

## Evidence and release gate
Build 79 is a development candidate, stacked on Build 78. Build 77 (PR 68) passed 667 core tests and 165 browser tests. Build 78/79 must pass their own checks before merging. These counts do not prove native performance or entertainment quality.

## Content inventory
Source review: 153 regular careers, 10 special careers, 102 ordinary achievement definitions (25 engine + 77 additional), 50 ordinary challenges (8 engine + 42 additional), 5 lineage goals and 5 hidden discoveries, 8 arcade games, 6 recent dramatic stories with 18 chapters, and 8 specialist circuits. The historical README reports 1,109 scenario cards and 3,089 options; the new runtime audit is the authority for exact current totals. The scenario generator contains 173 authored premises expanded into 692 context variants; do not describe all cards as independently written stories. The remaining cards are counted separately. Separate chapters and mini-games are not added to the scenario-card total.

Run `npm run audit:catalog` for actual engine inventory, duplicate IDs and invalid cards.
Run `npm run audit:simulation -- 60` for 18 seeded lives (3 modes × 6 countries, up to 60 annual cycles each) with validated state, JSON round trips, maximum save bytes, NPC counts and observed median/p95/max annual processing time. Optional argument 1–110 years. The CI smoke test covers three modes in one country for 18 years each. The full run and timing on actual hardware remain to be performed. No fixed performance claim or throughput threshold is made. Seeded rest-and-first-choice trajectories are not exhaustive player behavior.

## Fixes
Random starts previously used low-order LCG bits to choose country and background, producing correlated selections. Mixed 32-bit sampling now decorrelates consecutive seeds. A regression checks all 24 country/background pairs. Live dynasty refresh no longer computes net worth unnecessarily for a death-only objective; milestone evaluation follows economic cleanup. Existing saves and mode inheritance are unchanged.

## Competitive review (2026-11-28)
Official public references:
- https://apps.apple.com/us/app/bitlife-life-simulator/id1374403536
- https://play.google.com/store/apps/details?id=com.candywriter.bitlife

BitLife is a released, long-running choice-based life simulator with career/relationship choices, scandals, identity customization and regularly promoted challenges; its listings show additional specialist content and in-app purchases. Lifely has a promising differentiator in interconnected NPC households, regional companies and investments, family succession, persistent dramatic arcs, and offline skill-puzzle activities. It has not been established that those systems are deeper than BitLife's in practice. BitLife has the clear advantage in demonstrated public release maturity. Exact BitLife scenario and achievement counts are not verified and must not be invented. Feature availability is not a substitute for human playtesting.

## Prioritized quality gates
P0: Verify all CI jobs; audit full catalog and long-lived saves; resolve invalid states, save failures and blocked interactions; build signed native candidates and check real iOS and Android devices (small screens, background/foreground, audio mute, accessibility, install/update, save recovery).
P1: Measure annual processing time and memory on devices with long saves; conduct a balance pass across all modes; recruit independent testers to play equivalent lives in both games, tracking time to first meaningful decision, confusion, repeated choices, perceived agency, session enjoyment, and desire to return. Do not claim superiority before evidence.
P2: Improve the most shallow loops: football/basketball and racing puzzles into stateful matches, rhythm activity into interactive timing, more independently authored stories, shorter navigation paths and more distinctive presentation. Focus on play quality instead of more financial subsystems.

No TestFlight upload, store submission, signed build, physical-device benchmark or independent comparative playtest was performed by this change.
